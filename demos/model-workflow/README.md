# 模型工作流 demo（旧版独立实现）

本目录来自原项目旧版，包含真实HTTP模型调用路径。保留独立页面，同时已经通过Vite代理接入根目录React分析页。作者确认此前NLP使用DeepSeek API、图像部分使用千问；当前找到的源码是单一Base URL/Key的兼容接口实现，不能证明当时双提供方配置或千问图像生成已完整保留。

## 启动

使用Node.js 22，无需第三方依赖：

```bash
cd demos/model-workflow
cp .env.example .env
# 在本机编辑 .env，填入自己的API Key
node --env-file=.env server.mjs
```

访问 http://127.0.0.1:8899 。没有Key也可用 `npm start` 查看页面；点击分析会明确报“模型服务未配置”，不会回退成模拟结果。

默认示例为DeepSeek文本配置且关闭图片输入。图片内容理解需要支持视觉的模型和兼容接口；当前服务共用一个endpoint和key，不能直接同时路由到两个独立服务。VISION_MODEL控制图片理解，不是图像生成。此demo输出设计简报、生成Prompt、溯源表与素材描述；没有找到千问生图专用endpoint。不要把生成Prompt写成已生成IP图片。

点击“载入海窝子示例”载入虚构测试意见，再“开始分析”。启用真实服务会将你填写的文字/图片发送给所配置提供方，可能消耗账户额度；演示请用虚构材料。Key仅由服务端环境变量读取。

## 实现与检查

`POST /api/workflow/analyze`顺序执行预处理、文本提取、图片理解、多模态关联、聚类与权重、分歧、转译、输出；服务端调用 `/chat/completions`。`GET /api/model/status`返回配置状态，不返回Key。

`npm run check`执行语法检查。此次未使用真实Key、未重跑付费推理，因此只能确认代码调用路径和无Key错误处理，不能宣称最新运行成功。前端仍保留旧规则辅助函数，但开始分析按钮走服务端fetch，失败不会返回本地模拟输出。进度节点并非服务端逐节点实时推送。

发布副本仅做两项必要修正：静态资源改用白名单，防止.env或服务端代码被HTTP下载；旧示例人物称呼替换为虚构参与者。原件未改动。仅用于本机演示，未进行公网部署验收。

实测补充：2026-10-29，首页HTTP 200、模型状态接口200且configured=false；无Key分析返回400；/.env及/server.mjs均返回404。语法检查通过。未进行真实模型推理。
